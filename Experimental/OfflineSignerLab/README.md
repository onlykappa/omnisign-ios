# Offline signing laboratory — isolated, AGPL-3.0-only

This package is NOT linked to the OmniSign app and enables no app signing/install button. It evaluates CodeSignKit revision d0c67710fda9a2646b9e829cb2cf443892728371 using an ephemeral generated self-signed RSA identity and disposable `org.omnisign.lab` code. That identity is NOT Apple-issued; no iPhone installation or developer-account authorization is implied.

The executable rejects other root bundle identifiers and symlinks. It reads a synthetic PKCS#12/password file locally, never sends/logs secrets, and never touches Apple accounts, Keychain identities, provisioning, installed apps or user certificates. A successful command is only a candidate output; the macOS harness must independently run Apple's codesign verifier against every nested target and the parent, then prove a tampered resource is rejected.

CodeSignKit is mirrored from a pinned source revision under ../Vendor/CodeSignKit, with reviewed experimental patches listed in UPSTREAM.md, and carries AGPL-3.0; this isolated wrapper is AGPL-3.0-only. Its manifest pins swift-crypto 4.3.1 and swift-asn1 1.6.0. Both Apple projects carry Apache-2.0 with their included notices; swift-crypto's vendored crypto code has additional notices that must accompany any redistribution. Resolve/audit all transitives and preserve the checked-in lockfile and source availability. The minimal mirrored manifest excludes the upstream test/CLI OpenSSL binary target. This is not part of the MIT application dependency graph.

No lab binary, private key, P12, password or generated certificate should be uploaded as a CI artifact. Only sanitized verification results may be uploaded. The harness uses a disposable temporary directory and deletes only its own generated files. Do not feed real owner signing assets into this experiment. Before any distribution of a derived binary, complete the transitive license/security review and offer corresponding source as required by AGPL.

Reproduction (macOS with Xcode): `scripts/signing-lab.sh` from the repository root. Build-only (Linux/macOS Swift 6+): `swift build --package-path Experimental/OfflineSignerLab --jobs 2`. Actual verification status is recorded in docs/v2/TEST_RESULTS.md; these instructions alone are not a pass.

Source audit cautions: candidate patches now reject resource-read failures and wrong requirement encodings; PKCS12 parsing/private-key matching and MAC handling still require a full audit; the CMS builder falls back to embedded Apple chain certificates; designated requirements assume an Apple anchor. The generated self-signed identity cannot establish that anchor. Do not weaken the native verifier or relabel primitive checks as a full valid Apple signature. Controlled readable fixtures and independent verification bound this experiment; these issues block direct production integration.

The independent Swift CMS verifier is a separate target that imports Crypto/CryptoExtras, **not CodeSignKit**. It checks a bounded detached RSA/SHA-256 SignedData subset, matches issuer/serial to the signing public key, verifies the signed content digest and DER attribute signature, and always reports Apple trust/certificate-time/installation authorization false. Four tests use an independent public OpenSSL-generated vector and negative content/signature/DER cases. The Mac harness cross-checks each generated code signature with both Swift and OpenSSL, plus page/resource hashes; native Mac structural/cryptographic validity remains a separate check and does not establish Apple development trust. Public fixture CMS/certificates contain synthetic metadata and no private key; generated P12/passwords remain local and unuploaded.

Native rejection diagnostics are retained only for the controlled generated app, with temporary paths replaced and output bounded. The native verifier never receives key/P12/password paths and cannot read them from the app bundle. `csreq` separately checks whether the candidate designated-requirement blob parses; this diagnostic does not replace or weaken `codesign --verify --deep --strict`. Native rejection must fail the current harness regardless of primitive checks. A separate explicit Apple-anchor requirement must reject the synthetic certificate.

The source mirror now corrects designated-requirement type/equality encoding and makes resource hashing stream/fail closed rather than hash empty bytes after read errors. Two additional regression tests cover these defects (six lab tests total). The generated leaf is restricted to an ephemeral self-issued lab identity with code-signing key usage/EKU; real Apple-issued assets are rejected. These fixes are experimental and do not complete PKCS#12, chain, profile, native-policy or device acceptance audits.
