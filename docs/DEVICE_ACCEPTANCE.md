# Physical iPhone acceptance — NOT RUN

Target: owner-confirmed iPhone 17 running iOS 27.0.1. Record actual model identifier, OS build, Xcode/SDK, OmniSign commit, signing backend commit and transport backend commit. Keep device identifiers and credentials out of shared reports.

**Stop gate:** the current build cannot perform signing, installation or refresh. Do not bypass its disabled operations. First complete and audit the backends described in PHASE0.md. The following is the future acceptance procedure, not a claim that it is currently executable.

1. Build OmniSign with a compatible Xcode SDK. Bootstrap using an owner-authorized signing method. A Windows PC may be used only for this initial signing/pairing and emergency recovery. Confirm Developer Mode and profile trust as required by the device; never disable OS security through an exploit.
2. Build a disposable app with a unique identifier, a visible version/build, and a text field whose value is persisted in its own container. Prepare v1 and v2 with the same identifier and team. Include a nested framework and extension test variant. Never use the owner's Kodi/KappaForge as test subjects.
3. Import v1 through Files and inspect metadata, frameworks, extension identifiers, actual entitlements and executable architectures. Separately test hostile fixtures and an unsupported entitlement; expect a precise refusal before signing.
4. Import authorized pairing credentials locally. Confirm cryptographic compatibility and a real authorized device-service handshake. Record VPN routing and service reachability independently; a VPN indicator alone is not success.
5. Authenticate the owner locally using a reviewed flow. Inspect an existing development certificate, expiration, Apple trust, matching accessible private key and profile device coverage. Never revoke unrelated certificates. Stop at account restrictions or 429/503; no repeated auth attempts.
6. Disable all desktop signing/install daemons, disconnect USB and keep the computer disconnected. Sign independently on-device; verify every nested signature, profile association, resource seal and parent signature with independent validation. Collect hashes and stage outcomes in a private test record.
7. Transfer and install through the paired device service. Require install completion plus inventory evidence matching identifier, version and embedded profile. An accepted transfer is not installation. Launch manually in the foreground and record the observed version. General app-launch verification is not assumed available through public sandbox APIs.
8. Enter a unique test value. Refresh before the actual profile expires. Verify installation/profile expiration changed and confirm the app launches with the saved value intact.
9. Import v2 and compare installed/new identifier, team, capabilities and version. Attempt only a compatible in-place update. Confirm v2 launches and the value survives. If replacement would require deletion, stop; record consequences and obtain explicit owner confirmation for the disposable app only.
10. Repeat with no computer connected. Reboot the phone; test VPN loss, expired/invalid pairing, insufficient storage, locked device, interrupted transfer, expired profile and app foreground/background transitions. Recovery must preserve the previously installed app and cap distinct nonauth attempts at five.
11. Export only allowlisted diagnostics: stage/category, numeric backend code and HTTP status, operation UUID, timestamps, app test version and backend revision. Inspect the export manually for secrets before sharing. Record -80045/-80046/7460 with their backend namespace; do not infer a universal meaning.
12. Only after repeated success consider owner-authorized Kodi/KappaForge imports. Inspect each actual IPA; verify entitlements/native code independently. Never automatically delete them or claim their data survives based on disposable-app results alone.

Pass requires all sign/install/launch/refresh/update/data checks to complete on the actual target without an active PC. Automated tests cannot close this gate. No uninterrupted background refresh guarantee is permitted; schedule user reminders and use supported opportunities only after those paths exist and are tested.
