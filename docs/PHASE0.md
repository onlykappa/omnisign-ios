## Decision

**Gate closed for signing/install/refresh and production release. Inspection/diagnostics development permitted.** Source demonstrates plausible components, not independent operation on iPhone 17/iOS 27.0.1. Linux has no iOS SDK, Xcode, device connection or Apple account assets. A portable Swift toolchain was obtained for core tests; it does not provide iOS frameworks or code-signing validation tools. No Apple authentication calls were made.

Stock iOS sandboxing does not expose a general public API allowing an arbitrary free-provisioned app to sign in to Apple's developer services and install arbitrary IPA packages. Cryptographic signing can be implemented as a userspace library; installation additionally needs authorized device services and a usable transport/pairing mechanism. Free provisioning does not confer the entitlement needed for an embedded Network Extension. SideStore's separate VPN companion is a significant deployment constraint. No fundamental impossibility is proved, but a complete free-only single-app transport is not established.

## Important source findings

SideSign `AppBundleSigner.signApp` chooses a matching profile and otherwise falls back to the first profile. OmniSign must refuse missing exact app/extension mappings rather than adopt that fallback. Its entitlement rewriting changes keychain group prefixes and omits capabilities absent from the profile; these decisions can alter application behavior and data access. They need explicit compatibility analysis.

SideSign authentication verbose logs contain Apple IDs and SRP challenge material, and certificate/profile logs include identifiers. These logs must not be connected to OmniSign's diagnostics. Existing certificate lookup is safe only with a matching accessible private key. SideSign exposes revocation; OmniSign has no revocation adapter. No certificate mutation or account login occurred.

A development certificate binds a public key to a team; signing needs the matching private key. A provisioning profile is an Apple-signed CMS container binding application identifiers, team, authorized certificates, entitlements, device coverage and expiration. Parsing its plist without CMS chain validation is inspection only. A correct IPA signer must produce nested CodeDirectories/resource seals/CMS and validate them independently. Archive CRC checks are unrelated to Apple signature trust.

## Sideloadly compared with SideStore

Sideloadly normally runs authentication/provisioning, IPA rewriting/signing and device transfer on a Windows/macOS host using Apple device connectivity. Its desktop refresh/daemon workflow is not an on-device backend OmniSign can silently reuse. Sideloadly's full signing implementation is not source-verified here; this comparison describes its documented desktop workflow, not audited internals. Product reference: https://sideloadly.io/ .

SideStore moves account/provisioning orchestration and signing into the iOS process and reaches installation services through pairing plus local VPN/device transport. Bootstrap/recovery may still require a computer. Its transport is not supplied merely by bundling a signing library. OmniSign would need its own audited orchestration and independently provisioned transport, without requiring the SideStore app to remain installed.
